# cairn-md — consignes pour Claude

## Le projet
- **Cairn** : appli perso de prise de notes en Markdown, des notes empilées et reliées par des liens `[[Titre]]`. Dépôt et URL : **Tirashi/cairn-md** (GitHub Pages) ; nom affiché dans l'interface : « Cairn ». Un seul utilisateur.
- **Cahier des charges : [`specs/plan-v1.md`](specs/plan-v1.md)** (modèle de données, structure, étapes 1 à 7, portabilité). **Le lire avant** de toucher au schéma, à l'accès aux données, à l'export/import ou au thème.
- Front statique en **HTML/CSS/JS vanilla, sans build** : le fichier poussé est celui que sert GitHub Pages. Bibliothèques **via CDN, version exacte épinglée** : `supabase-js`, `marked`, `DOMPurify`, `JSZip`. Pas de npm.
- Backend : **Supabase** (authentification + table `notes`, notes en Markdown brut dans `content`). Inscriptions publiques désactivées.
- Structure : `index.html` (tous les écrans : chargement, config manquante, connexion, appli), `css/style.css`, `assets/` (`logo.svg`, `icon-maskable.svg`), `js/` en **modules ES** (`main.js` choix de l'écran et routage par hash, `config.js`, `supabase.js` client + fonctions d'auth, `auth.js` écran de connexion, `theme.js` bascule sombre/clair, `notes.js` CRUD, `markdown.js` rendu assaini + coloration de l'éditeur, `ui.js` orchestration (liste, éditeur, sauvegarde, routes `#/` et `#/note/<id>`, renommages), `arbre.js` dossiers/tags/filtres (fonctions pures), `liens.js` liens `[[…]]` (fonctions pures), `navigation.js` arbre + tags + fil d'Ariane mobile, `meta.js` champ dossier et tags de la note, `suggestions.js` listes de suggestions au clavier, `dialogue.js` dialogue unique, `palette.js` fenêtre « lier une note » (recherche + filtres), `defilement.js` défilement lié éditeur ↔ aperçu en split (chaque bloc de l'aperçu accroché à sa ligne de Markdown, `debutsDesBlocs` dans `markdown.js`), `listes.js` Entrée qui continue une liste `-` / `- [ ]` / `1.` (fonction pure), `taches.js` tâches `- [ ] …` d'un Markdown (`listerTaches`, `basculerCase` ; cases cochables de l'aperçu et page « tâches ouvertes » `#/taches`, fonctions pures), `historique.js` fenêtre « historique » (versions groupées, différences, voir, restaurer), `rendu-avance.js` code coloré + mermaid dans l'aperçu (chargés à la demande), `export.js` zip, en-tête YAML, analyse et application d'un import (logique, sans interface), `import-dialogue.js` fenêtre d'import (récapitulatif, détail d'un conflit, progression), `local.js` copie locale IndexedDB + file d'attente (sans réseau), `sync-dialogue.js` conflits de synchronisation, `installation.js` service worker + carte et menu « installer »), `sw.js` (service worker, à la racine), `manifest.webmanifest`, `assets/icon-192.png`, `icon-512.png`, `apple-touch-icon.png` (tirés d'`icon-maskable.svg`), `supabase/schema.sql`, `supabase/versions.sql` (historique), `outils/` (essais), `maquettes/`.
- Versions épinglées (`+esm` sur jsDelivr) : `supabase-js` **2.118.0** (`js/supabase.js`), `marked` **18.1.1** et `DOMPurify` **3.4.17** (`js/markdown.js`), `@highlightjs/cdn-assets` **11.12.0** (`es/highlight.min.js`) et `mermaid` **12.2.0** (`dist/mermaid.esm.min.mjs`, en morceaux) dans `js/rendu-avance.js`, **importés seulement si la note a du code ou un diagramme** ; `jszip` **3.10.2** (`+esm`, chargé seulement à l'export ou à l'import ; l'essai sert le fichier UMD `dist/jszip.min.js` suivi de `export default window.JSZip`) ; Playwright **1.63.0** dans la CI. L'essai prend ces bibliothèques sur le registre npm à la version lue dans `js/` (cache `outils/.cache/`, ignoré par git, mis en cache dans la CI).
- **Dossiers et tags** (étape 4, direction A « chemin éditable ») : dossier = chemin `A/B` normalisé (`normaliserDossier`), casse d'un dossier existant reprise ; tags en minuscules sans `#` ni espaces. **Recherche faite dans le navigateur** sur les notes déjà chargées (titre + contenu, sans accents ni casse) au lieu d'un `ilike` côté serveur : même résultat, instantané. Liens `[[Titre]]` / `[[Titre|texte]]` résolus sans tenir compte de la casse (extension `marked`, jamais dans le code).
- **Aperçu enrichi** : le SVG de mermaid repasse par DOMPurify (profil svg, `htmlLabels: false`, `securityLevel: 'strict'`) ; thème mermaid tiré des variables CSS, redessiné au changement de thème (événement `cairn-theme`). Détection auto du langage limitée aux langages courants (seuil de pertinence 3), sinon le code reste brut.
- **Export / import** (étape 6, direction A + détail C) : chemin `dossier/slug.md` (doublon → `-2`), en-tête avec chaînes en JSON (valide en YAML) ; la lecture accepte aussi un en-tête écrit à la main (guillemets simples, listes `[a, b]` ou `- a`). Classement : `id` connu → identique / modifiée / conflit (`updated_at` de Cairn plus récent que celui du fichier, ou absent) ; sans `id` → nouvelle, ou conflit si le titre existe. Les notes importées passent par `notes.js` (créer / modifier une à une), puis la liste est rechargée depuis le serveur. Sur téléphone, thème et logout sont dans le menu `⋯`.
- **PWA et hors ligne** (direction A + carte d'installation de B + conflit de C) : `sw.js` sert les fichiers de Cairn **réseau d'abord** (cache si pas de réseau ou plus de 3 s), le CDN et la police **cache d'abord** (URL versionnées), jamais Supabase. **Tout nouveau fichier de l'application va dans la liste `COQUILLE` de `sw.js`** (l'essai vérifie `js/`) ; changer `VERSION` seulement si un fichier est renommé ou supprimé. Les notes hors ligne sont dans **IndexedDB** (`local.js`) : `notes.js` écrit sur le serveur s'il répond, sinon dans la copie locale + file d'attente (une entrée fusionnée par note, avec l'`updated_at` serveur de départ) ; au retour du réseau (`online`, ou toutes les 30 s), la file est rejouée ; serveur plus récent que la base → conflit (`cairn-sync` annonce l'état). Une note créée hors ligne garde son `id` (uuid du navigateur). Copie effacée à la déconnexion (avertissement s'il reste des envois) et quand un autre compte se connecte. Hors ligne, une session expirée ne renvoie pas à l'écran de connexion (`sessionGardee` dans `supabase.js`).
- **Plusieurs appareils** (06/11) : `actualiser` (`ui.js`) au retour au premier plan (`visibilitychange`, `focus`) et toutes les 60 s si visible : `changementsServeur` (`notes.js`) lit `id, updated_at`, puis le contenu des seules notes changées (trafic Supabase minimal : ne **jamais** recharger toutes les notes en boucle). Sauvegarde avec `base` (updated_at connu) : `update … eq('updated_at', base)` ; aucune ligne → la note a changé ailleurs → conflit (même fenêtre que le hors ligne), rien n'est écrasé. La note ouverte n'est remplacée que si aucune frappe n'attend (`frappeEnCours`).
- **Historique** (direction A) : table `note_versions` remplie **par la base** (trigger `garder_version` dans `supabase/versions.sql`) avec l'état d'avant chaque changement de titre ou de contenu, au plus une toutes les 10 min par note ; tri `trier_versions` (tout 24 h, puis 1/jour 30 j, 1/semaine 1 an, 1/mois ; 50 max). Restaurer = `notes.js` ajoute l'état actuel comme version puis remet contenu, dossier, tags (pas le titre). Différences ligne par ligne : `differences` dans `export.js`. Réseau nécessaire ; pas dans l'export.
- **Éditeur** : `<textarea>` transparent posé sur les lignes colorées (`#editeur-fond`, une `.ed-ligne` par ligne, numéros en CSS). Les deux couches doivent garder exactement la même police, taille, marge et coupure : la coloration ne change **que les couleurs** (pas de gras réel, pas de taille différente).
- **Direction visuelle retenue (05/11) : B « Terminal »** de la [maquette](https://claude.ai/artifact/5bt29wqWkuZcnrFtcC32sZ) (`maquettes/interface/`) : tout en JetBrains Mono, coins de 6 px, filets `#2a2d33`, dossiers en arborescence `├─`, notes affichées comme `nom.md`, recherche façon invite `>`, éditeur avec numéros de ligne et Markdown coloré, suggestions à la frappe de `[[`, barre d'état (enregistré, liens entrants). Desktop : barre du haut, dossiers/tags (240 px), liste (320 px), note en `edit | split | view` avec liens entrants sous l'aperçu.
- Identité : esprit ludique, minimaliste, geek ; **thème sombre par défaut** (fond `#121212`, texte `#e6e6e6`, accent ambre `#f0b45a`), couleurs en variables CSS sur `:root`, redéfinies par `[data-theme="light"]`. Le logo (trois tablettes de pierre, `[[ ]]` gravé en bas) est fourni : ne pas le redessiner sans demande.
- Projet voisin : la **Ludothèque 16 bits** (**Tirashi/Claude**), dont ce fichier reprend les règles de travail. Les deux projets restent **indépendants** (pas de base ni de code partagés).

## Règles techniques de Cairn
- **Un seul point d'accès aux données** : seuls `js/supabase.js` et `js/notes.js` parlent à Supabase (aucun autre fichier n'importe `supabase-js`). URL et clé `anon` uniquement dans `js/config.js`. But : pouvoir migrer vers un VPS en ne touchant que ces fichiers.
- Schéma en **Postgres standard** (seul `auth.uid()` est propre à Supabase) ; toute modification du schéma va dans un fichier SQL du dépôt et dans le cahier des charges.
- Tout HTML rendu depuis du Markdown passe **toujours** par `DOMPurify`.
- `localStorage` seulement pour les préférences (thème, mode, « plus tard » de l'installation…), toujours dans un `try/catch` ; les notes hors ligne vont dans IndexedDB (`local.js`).
- Responsive : mobile = un panneau à la fois ; desktop = 3 colonnes en CSS Grid ; cibles tactiles ≥ 44 px.

## Tenir la documentation à jour
**Cycle d'un projet** : **idée** = quelques lignes dans `IDEES.md` ; dès qu'on la travaille (maquette, décisions), elle devient un **chantier** avec son fichier `specs/<chantier>.md`, et `IDEES.md` ne garde qu'une ligne qui y renvoie. Ne rien effacer : une idée abandonnée garde une ligne (❌ et la raison).

À chaque chantier, quand c'est pertinent : `CLAUDE.md` (nouvelle règle, **une ligne** dans « En cours ») ; `specs/suivi.md` (détails du chantier) ; `IDEES.md` (✅, nouvelles idées, préférences) ; `README.md` (description pour les utilisateurs).

## Leçons apprises
- **Éditeur aligné** (05/11) : chaque `.ed-ligne` doit garder une hauteur, même vide et même dans un bloc de code (caractère invisible `\u200b`). Une ligne de hauteur nulle décale tout le texte affiché par rapport au curseur réel. L'essai vérifie l'alignement sur une note plus haute que l'écran (sinon la mesure est faussée).

- **Mise à jour de l'appli** (06/11) : GitHub Pages fait garder les fichiers 10 min par le navigateur ; le service worker les demande donc en `no-cache` (sinon un ancien `ui.js` peut côtoyer un nouveau `notes.js` et l'appli casse). Après « mets à jour main », dire à l'utilisateur de recharger (PC : Ctrl+Maj+R ; appli installée : fermer et rouvrir deux fois). Vérifier aussi que la publication **« pages build and deployment »** de `main` a réussi (06/11 : elle a échoué deux fois côté GitHub, « Deployment failed, try again later » ; le site servait l'ancienne version) ; sinon la relancer (`rerun_failed_jobs`).

- **Maquettes** (06/11) : une maquette = **une** idée, avec seulement ce qui a été demandé ; les ajouts se proposent en texte, à part. Une maquette trop riche (note du jour + tâches + semaine + accueil) n'a pas été comprise.
